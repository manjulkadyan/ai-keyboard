# Sprint 4: Money and looks (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A Pro subscription that Play sells, kb-api verifies and the app and the IME both honour within 2 s.
- A paywall with the eight PRD triggers, a "Fix payment" banner, and restore.
- AdMob ads in the app only (never in the IME), behind UMP consent, persisted caps and the app-open rules.
- In-app updates, typed Remote Config with a DataStore mirror for the IME, and Firebase Analytics as the release sink.
- 12 original theme presets with live preview, key border on/off and 4 original key sounds.
- The full FR-09 Settings tree, "Delete my data", and a Data safety draft.
- Exit: a closed testing build on Play, the §6.4 mid-tier gates green, and the Data safety form drafted.

**Architecture:**

*Billing.* A new Android module `:core:billing` wraps Play Billing behind a `BillingGateway` interface.
- `EntitlementRepository` is the single source of Pro state on the device.
- It never trusts a local Play purchase alone. It sends the token to kb-api and caches the signed answer.
- The cache is mirrored into `FeatureSettings` (multi-process DataStore). The IME reads only the mirror through its existing `() -> Boolean` gate.
- The kb-api HTTP calls (`EntitlementClient`, `AccountClient`) live in `:core:ai`, next to `AiClient`, because `:core:ai` is the kb-api client.

*Backend.* kb-api in `backend/` (git submodule) gets `/v1/entitlement/verify`, `GET /v1/entitlement`, `/internal/rtdn` and `/v1/account/delete`.
- It reads the subscription from the Play Developer API, acknowledges it, and stores it in the S3 `EntitlementStore`.
- The S3 `TierResolver` then returns PRO without change.

*Ads.* `:core:ads` gets the GMA SDK, the PRD placements and a pure `AdEligibility` rule set.
- The ad views and managers live in `:app` under `com.manjul.aikeyboard.app.ads`, the only package `ImeAdIsolationTest` allows.

*Config.* `:core:config` gets a typed key catalog. `:core:firebase` gets the Firebase RC source, the Analytics sink and the Crashlytics reporter.
- RC values are activated at app cold start and copied to a DataStore mirror. The IME reads the mirror and never fetches.

*Themes.* A new pure module `:core:theme` holds `ThemeSpec`, the presets and a generator that writes Snygg v2 JSON.
- A new tool `:tools:themegen` writes the stylesheets and the key sounds into `app/src/main/assets` and `res/raw`. The output is committed, like the dictionaries.
- Upstream `ThemeManager` loads them as a normal theme extension, so changes apply live.

**ARCH-006 Client Code Complexity (Zocdoc standard)**
- Entitlement decisions and purchase verification live in kb-api (`backend/` (git submodule)).
- The app only shows the entitlement state and launches the billing flow. A local Play purchase never unlocks Pro by itself.
- API contract changes stay backwards compatible with older app versions:
  - New endpoints and new response fields only. No field is renamed, removed or retyped.
  - The S3 app (no billing) keeps working against the S4 backend as a FREE user. A contract test proves it (Task 3).
  - New response fields are optional for the client. A missing `state` maps from `pro_active` (Task 2).

**OPS-001 Observability, logging part (Zocdoc standard)**
- Never log PII or credentials at any level.
- For billing, never log purchase tokens, order IDs tied to a user, or auth headers. This covers exception messages, `toString()`, analytics params and WorkManager data.
- WARN means a retry or fallback recovered. ERROR means the user-facing feature failed.
- DEBUG and TRACE stay off in release. R8 already strips `android.util.Log` and `Flog` (`app/proguard-hardening.pro`). The backend sets the root level to INFO in prod.
- No standards exist for Play Billing, RTDN, AdMob or themes. The repo CLAUDE.md rules cover those areas.

**Privacy and data handling**
- No user content in any log, analytics event, exception, crash key or backend log (PC-10, TRD §5.4). User content means typed text, suggestions, transcripts, AI input or output, clipboard text and host package names.
- No ads anywhere from O1 to O6 or in the first session. No paywall before `ime_selected`.
- No IME action opens an Activity that shows an ad straight away. The paywall never shows an ad.
- No interstitial or app-open ad on a screen reached from PROCESS_TEXT, SEND or a notification.
- Every feature that sends or stores data adds a row to `docs/data-flows.md` in the same task.

**Keys and secrets**
- No vendor key in the APK, RC, either repo or test fixtures.
- The entitlement signing private key and the Play service account live only in Secret Manager. The APK holds only the public key.
- The AdMob app id and ad unit ids are not secrets. They come from the Gradle property `aikb.admob.appId` and from RC.

**Analytics and copy**
- Event names are snake_case, at most 40 chars and 25 params, registry-checked. PRD §12 names are canonical.
- All user-visible copy goes in `values/strings_fork.xml` (or the module's own `strings.xml`). English only, translatable, no concatenation.
- Prices always come from `ProductDetails`. No price literal in code or strings.

**Banned**
- `fallbackToDestructiveMigration`, `Process.killProcess`, `System.exit`.
- SDK auto-init at process start. `FirebaseInitProvider` and the GMA init provider are removed from the merged manifest.
- Deriving any code, art, sound or copy from either teardown APK.

## Decisions taken in this plan (flag to product if wrong)

1. **PBL 9.1.0.** TRD §2 says to take 9.x if it is stable at Sprint 4. 9.1.0 is the current release. `enablePendingPurchases(PendingPurchasesParams)` and `enableAutoServiceReconnection()` are set.
2. **kb-api is the only Pro authority (ARCH-006).** The device caches kb-api's signed answer. The cache is valid until `expires_at` plus 3 days of grace. After that, the user is FREE until the next successful check.
3. **One purchase token links to one uid at a time.** A verify from a new uid (reinstall, new device) moves the link. This makes restore work without Google sign-in. A shared token moves Pro, it never copies it.
4. **The entitlement signature is ECDSA P-256 (`SHA256withECDSA`).** Ed25519 is not available on API 26. The signed payload is `v1|<pro_active>|<state>|<expires_at_ms>|<issued_at_ms>`. The public key comes from the Gradle property `aikb.entitlement.publicKey`. A release build fails when it is empty.
5. **Pro reaches the IME through `FeatureSettings` only.** The store is a `MultiProcessDataStore`, so it already crosses processes. There is no separate broadcast while the app and the IME share one process (OD-12 option A). If OD-12 moves to option B, add the broadcast then.
6. **The integrity verdict refreshes on each App Check verification.** kb-api records `integrity_at = now` for the uid whenever a real App Check token verifies. Dev auth never records it. This satisfies TRD §11.4 ("fresh verdict on verify and once per 24 h") without a second integrity call.
7. **Photo backgrounds are v1.** The PRD lists them under v1. The TRD S4 line lists them for S4. `ThemeSpec` keeps the `IMAGE` type and the blur fields, so v1 adds no model change. The generator supports `COLOR` only in S4.
8. **12 presets: 8 free and 4 premium.** The premium ones exercise the 👑 badge and the T3 paywall. The 20+ premium presets are v1.
9. **Presets are colour only, and key sounds are synthesized by `:tools:themegen`.** So all art and sound is ours by construction. `assets/LICENSES` records both.
10. **Pro benefits shown are only the shipped ones.** No ads, 150 AI actions a day, premium themes, auto-polish. The cloud translation tier (T5) waits for `/v1/translate`. Premium stickers (T6) wait for S5. Both trigger ids exist in the enum but no UI uses them yet.
11. **AdMob and UMP only (OD-06), legacy GMA (OD-09), no mediation.**
12. **UMP runs only after `onboardingDone`.** Pro users skip both UMP and `MobileAds.initialize`. The ad privacy options row is then hidden.
13. **The app and the IME stay in one process (OD-12 option A).** Task 13 measures TRD §11.1 #1.2 (IME PSS ≤ 120 MB 60 s after a native ad screen). A miss goes to product as an OD-12 option B request.
14. **"At least 2 completed uses"** counts completed feature uses since the session start or the last interstitial, whichever is later. A completed use is a `translate_done` on the translator surface, a copy or reuse in History, or a theme apply.
15. **A new ad session** starts at a MainActivity cold start, or on a return after at least 30 min in the background.
16. **No app-open ad after an external flow returns.** Returning from Play Billing, the UMP form, the update flow, the share sheet or a browser does not count as an app open.
17. **Firebase Analytics and Crashlytics use the default `FirebaseApp`**, created manually on first use in the app process. The S3 named app `aikb` stays for App Check and Auth. Manifest defaults keep collection off until the consent and opt-out checks pass.
18. **T2 never opens the full paywall by itself.** The IME inline card has "See Pro", and a tap always opens the paywall. "At most once a day" is met because nothing opens it automatically.
19. **"Delete my data" needs the network.** It calls kb-api first and wipes locally only after success. "Clear data on this device" works offline and keeps the server rows.
20. **The local wipe keeps `onboardingDone = true`** so the app does not restart onboarding. Everything else in `FeatureSettings` returns to its default.
21. **The web deletion page is a static page without sign-in.** MVP has no Google sign-in, so no user-created account exists. The page explains in-app deletion, gives a contact address and says how to cancel in Play. The form arrives with Google sign-in.
22. **The IME-only cold-start test is an instrumented test, run on an emulator in the exit check.** `pr.yml` runs no connected tests today. A CI emulator job is an open question.
23. **The route `pro` stays as an alias of `paywall?trigger=ai_quota`** so S3 intents keep working.
24. **`price_tier` is the ISO currency code of the purchased offer** (for example `PKR`). It is not a price.
25. **A kill-switch RC update activates at once but changes only the kill-switch keys in the mirror.** Other keys keep their cold-start values until the next cold start.

## Review Focus

1. **The purchase callback arrives but verify fails or the device is offline.** The user never sees Pro flash on and off.
   - The paywall shows "Activating Pro…" and the repository retries with backoff until kb-api answers.
   - A `PENDING` purchase never gives Pro.
   - An app restart resumes the retry, so kb-api acknowledges within 3 days.

   Covered in Task 2.
2. **Pro changes while state depends on it.**
   - Pro starts: loaded ads are destroyed and no new ad loads in this session.
   - Pro lapses: an applied premium theme returns to the default in the app and at the next IME start. Ads come back at the next cold start, never mid-screen.

   Covered in Tasks 4, 7 and 10.
3. **An app-open ad on the wrong entry.** PROCESS_TEXT, SEND, a notification, a deep link to the paywall, onboarding, the splash, the first session, within 30 s of an interstitial, or a return from Billing, UMP, the update flow or a browser. None shows an app-open ad. Covered by the `AdEligibility` table in Task 7.
4. **RTDN replays and disorder.** A duplicate notification, notifications out of order, a token kb-api never saw, a refund or revocation, and a `linkedPurchaseToken` upgrade. Each one ends in the state that Play reports now, because kb-api always re-reads the subscription. Covered in Task 3.
5. **Credentials in logs.** Purchase tokens, order ids (`GPA.`), `Authorization` values and OIDC JWTs never appear in device logs, backend logs, exception messages or analytics. This holds on every error path, including a PBL or HTTP exception that echoes the request. Covered by log-capture tests in Tasks 2, 3 and 12.

Behaviour of `EntitlementRepository`:
- For each purchased token it calls `verify`. With no local purchase it calls `current()`, because RTDN can know about a purchase on another device.

- `OFFLINE` and `UNAVAILABLE` keep the cache, set `activating = true` after a purchase, and retry at 2 s, 4 s, 8 s up to 15 min. `VerifyPurchaseWorker` (unique, no input data) carries the retry across restarts. It re-reads purchases from Play.

  - `purchase_fail{code}` on `Failed` and `Cancelled` (`code = "user_canceled"`)
  - `subscription_state{state}` on each state change
  - `restore_purchases{found}`
  - `pro_status`: `free`, `trial`, `pro` or `grace`
