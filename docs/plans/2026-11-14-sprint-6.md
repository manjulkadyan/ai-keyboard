# Sprint 6: Roman Urdu and Hinglish transliteration (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Two new input modes, "Urdu (Roman)" and "Hindi (Roman)", on the QWERTY layout, with a "Beta" label.
- While the user types Latin letters, the strip shows up to 3 native-script candidates and a Latin chip.
- Space commits the top candidate only when the plan's space gate allows it. The Latin chip keeps the Roman text.
- User mappings (Roman word to native word), stored on the device and managed in settings.
- The same strip in the source line of the translate bar.
- Exit: every CI gate green, the smoke sets above their floor, and the device checklist done.

**Architecture:**

*Engine.* A new pure Kotlin module `:core:translit` (`aikeyboard.jvm.library`, depends on `:core:suggest`).
- `RuleTable` reads a plain-text rule file per language from the module resources.
- `BeamDecoder` segments the Roman input from left to right and keeps the best 16 partial outputs.
- `TranslitLexicon` is the data seam. `SdictLexicon` is the only implementation in S6. A later `PackLexicon` reads
  the Dakshina pack.
- `TranslitRanker` scores rule cost, lexicon presence, frequency and user mappings.
- `TranslitEngine` is the one entry point: `suggest(roman, max)`.

*IME.* A new `SuggestionProvider` in `:app` at `fork/translit/TranslitSuggestionProvider`.
- It is registered in `NlpManager` next to the Latin and Han providers. Two new subtype presets select it through
  `nlpProviders.suggestion`.
- The candidates are `TranslitCandidate` objects. `AutocorrectGate` sends them to the new `TranslitSpaceGate`.
- In the translate bar, `BarKeyRouter` feeds the Roman word in progress to the same engine through a small
  `BarTranslitController`.

*Data.* A new Room entity `TranslitMappingEntity` in `:core:database` (`AppDatabase` version 4, AutoMigration 3 to 4).
`fork/translit/CustomMappingsRepository` loads it into the engine's in-memory `CustomMappings`.

*App.* A "Roman typing" settings screen under Languages at `fork/translit/RomanTypingScreen.kt`.

**Tech Stack:**
- Kotlin 2.2.20, coroutines/Flow, Compose, Room 2.7.2, JUnit5 + Turbine, Robolectric 4.17.
- No new library in any module. `scripts/check-data-flows.sh` therefore needs no new artifact row.
- Never guess an API name. If you are not sure, compile against the jar (`javap`).

## Decisions taken in this plan (flag to product if wrong)

1. **Subtype tags are `ur-PK-roman` and `hi-IN-roman`, not `ur-Latn-PK` and `hi-Latn-IN`.**
   - `FlorisLocale.fromTag` splits on `-` and `_`. With three parts it builds `Locale(lang, country, variant)`, so
     `ur-Latn-PK` gives country `Latn` and variant `PK`.
   - Upstream uses a variant for `zh-CN-zhengma`. We do the same. `LatinSuggester.languageOf` and `Lang.of` still
     cut both tags to `ur` and `hi`, so the translate bar and the dictionaries see the right language.
   - The provider decides "Roman" from its own `providerId` in the preset, never from the tag.
2. **The presets go in our fork extension, not the upstream localization file.** `KeyboardExtension` supports
   `subtypePresets` (`KeyboardExtension.kt:41`), and `KeyboardManager` merges them (`:1006`). No upstream JSON changes.
3. **The space gate lives behind `AutocorrectGate`, not beside it.**
   - `AutocorrectGate.onSpace` and `onOtherKey` pass every non-Latin candidate unchanged (`AutocorrectGate.kt`).
   - Without a change, `onOtherKey` commits a translit candidate on punctuation. `onSpace` commits any candidate that
     is marked eligible.
   - Both functions send a `TranslitCandidate` to `TranslitSpaceGate`. `TranslitSpaceGate` does not read the
     autocorrect setting or `fieldAllowsAutocorrect`. `AutocorrectGate` is a fork file, so no upstream marker is needed.
   - On other keys (punctuation, enter), the Roman text stays. Only space commits a candidate.
4. **Backspace undo in the host uses a fork record, not the upstream revert path.** The spec says "through the
   `:ime:editing` own-write undo". In the host, a space commit goes through `commitCandidate`, which sets
   `phantomSpace.candidateForRevert`. The space that follows calls `commitText`, which clears that record, so the
   upstream revert path never sees a space commit. It also never edits the text: it only calls
   `notifySuggestionReverted`.
   - `fork/translit/TranslitRevert` keeps its own record. `KeyboardManager.handleSpace` records a native
     `TranslitCandidate` after the space goes in. Any other key, a strip tap or a hardware space clears the record.
   - On the next Backspace, `handleBackwardDelete` asks `TranslitRevert.undo`. It acts once, within 5 seconds, on the
     same input connection, and only while the text before the cursor still equals the native word plus the space.
     Then it replaces that text with the Roman word and calls `notifySuggestionReverted`, which removes the boost.
     The Backspace then deletes nothing more. A second Backspace deletes one character.
   - Every other candidate keeps the upstream behavior.
   - `OwnWriteUndo` is used in the translate bar, where the bar buffer is the target.
5. **The migration is `AutoMigration(3, 4)`.** The spec says `Migration(3, 4)`. Versions 2 and 3 use AutoMigration,
   and 3 to 4 only adds a table. `MigrationTest` gets a "v3 migrates to v4" case.
6. **The lexicon reads the shipped `.sdict` files as they are.** The spec says that the readers stay
   "memory-mapped". In fact `DictionaryFormat.read` loads the whole file into arrays. `ur.sdict` (1.39 MB) holds
   99,544 words as `String` objects.
   - Task 2 measures the heap of a loaded `ur` lexicon.
   - If the heap is above 6 MB, Task 2 adds a packed form inside `:core:translit`: one `CharArray` plus an offset
     `IntArray`. The `SuggestDictionary` is dropped after load.
   - `prefixExists` needs a prefix search. `SuggestDictionary` has none in public. Task 2 adds a public
     `hasPrefix(prefix): Boolean` (binary search over the sorted array) to `:core:suggest`. It is our module.
7. **The English check reuses a loaded English dictionary.** `LatinSuggester` holds only one language at a time, so
   in a Roman subtype it holds none. The provider loads `en.sdict` (468 KB) once, lazily, on the first word of 3
   letters or more. It counts toward the 8 MB budget. The threshold starts at frequency 160 (of 255) and Task 4 tunes
   it against the smoke sets.
8. **Space-commit field rule.** `TranslitFieldRules.allowsSpaceCommit(inputType, imeOptions, decision)` returns true
   only for `TYPE_CLASS_TEXT` with no `TYPE_TEXT_FLAG_NO_SUGGESTIONS`, no URI, email or password variation,
   `decision.allowSuggestionStrip`, and `!decision.sensitive`. It does not read `imeOptions`.
   `IME_FLAG_NO_PERSONALIZED_LEARNING` still blocks the space commit and the strip, because `SensitiveFieldPolicy`
   treats the flag as a hard reason and returns `PolicyDecision.Locked` (sensitive, no strip, no learning). Like
   `FieldAutocorrectRules`, a no-learning field gets no Roman candidates and no space commit. Product can relax the
   policy later.
9. **A tap on the Latin chip commits the Roman text plus nothing else.** It goes through `commitCandidate`, like any
   strip tap. It is a `TranslitCandidate` with `latin = true`, so it never counts as a native commit.
10. **The rule file format is TSV**: `roman<TAB>native<TAB>cost<TAB>position`, where position is `any`, `start`, `mid`
    or `end`. Lines that start with `#` are comments. Rows are sorted by `roman`. It is easy to diff.
11. **The in-memory boost lasts for the process.** It is a map of at most 256 entries, keyed by language and Roman
    word. It is cleared on `destroy()`, in incognito and by "Clear data".
12. **Smoke-set floor.** The floor is the measured top-1 and top-3 at the end of Task 6 minus 3 points, rounded down.
    It is a regression floor, not the PRD gate (spec "Evaluation").
13. **The `ur.sdict` rebuild with real counts stays out of S6.** The spec lists it as optional. It needs a source
    with a clean licence, and none is known today. Task 2 uses the rule-cost weighting for `ur` instead.

## Review Focus

1. **A native-script commit in the wrong field.** A sensitive field, a field without suggestions, a password, URI or
   email field never gets candidates or a space commit. Punctuation never commits a candidate. A rule-only candidate
   is never space-committed. Covered in Task 4 (`TranslitSpaceGateTest`, `TranslitSuggestionProviderTest`).
2. **Learning where it is not allowed.** Incognito and a no-learning field block the in-memory boost, "Save mapping"
   and the settings add. Covered in Tasks 3, 4 and 5.
3. **A regression in the native subtypes.** `ur-PK` and `hi-IN` keep the Latin provider, their layouts and their
   dictionaries. `findPreset` never returns a Roman preset for a native locale. Existing users get no Roman subtype.
   Covered in Task 3 (`DefaultSubtypesTest`, `TranslitPresetsTest`).
4. **English words in mixed text.** "hai" becomes "ہے", but "phone", "meeting" and "ok" keep Latin on space. Covered
   in Task 4 (`EnglishCheckTest`).
5. **Text leaving the engine.** No candidate, input or mapping appears in a log, an analytics param, an exception
   message or a `toString()`. `:core:translit` has no network or logging dependency. Covered in Tasks 1, 3, 5 and 6.

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces:
  ```kotlin
  enum class TranslitLang(val tag: String) { UR("ur"), HI("hi") }

  enum class Position { ANY, START, MID, END }

  class Rule(val roman: String, val native: String, val cost: Double, val position: Position)

  class RuleTable private constructor(val lang: TranslitLang, rules: List<Rule>) {
      val maxRomanLength: Int
      /** Rules whose roman part starts at input[offset]. Position is checked against offset and input length. */
      fun matchesAt(input: String, offset: Int): List<Rule>
      override fun toString(): String  // "RuleTable(lang=ur, rules=N)", no rule text
      companion object {
          fun parse(lang: TranslitLang, tsv: Sequence<String>): RuleTable
          fun load(lang: TranslitLang): RuleTable  // reads /translit/<tag>.tsv from the classpath
      }
  }
  ```

Rules:
- The input is lower-cased with `Locale.ROOT` before matching. Digits and punctuation never match a rule.
- `parse` rejects a line with a bad column count, a negative cost or an unknown position. The error message names the
  line number only, never the line text.
- Urdu: cover the consonant digraphs (`kh`, `gh`, `ch`, `sh`, `th`, `ph`, `bh`, `dh`, `zh`), the long vowels (`aa`,
  `ee`, `ii`, `oo`, `uu`, `ai`, `au`), the word-start vowel forms with `ا` and `آ`, and the endings (`a` to `ہ` or `ا`,
  `e` to `ے`, `i` to `ی`).
- Hindi: cover the same digraphs, the independent vowels at word start and the matras after a consonant. A consonant
  followed by a consonant gets a virama (`्`). A word-final consonant gets no virama (schwa deletion). The inherent
  `a` after a consonant maps to nothing.
- About 120 to 200 rows per language. The exact rows and costs are tuned in Task 6.

**Interfaces:**
- Consumes: `RuleTable`, `TranslitLang` (Task 1). `DictionaryFormat.read`, `SuggestDictionary` (`:core:suggest`).
- Produces:
  ```kotlin
  interface TranslitLexicon {
      /** 1..255 for a known word, null for an unknown one. */
      fun frequency(nativeWord: String): Int?
      fun prefixExists(nativePrefix: String): Boolean
  }

  class SdictLexicon(dict: SuggestDictionary) : TranslitLexicon {
      companion object { fun read(input: InputStream): SdictLexicon }
  }

  class CustomMappings {
      fun put(roman: String, native: String)
      fun remove(roman: String)
      fun replaceAll(entries: Map<String, String>)
      fun get(roman: String): String?
  }

  enum class Source { MAPPING, LEXICON, RULES }

  class Candidate(val native: String, val score: Double, val source: Source) {
      override fun toString(): String  // "Candidate(source=LEXICON)", no text
  }

  class BeamDecoder(private val table: RuleTable, private val lexicon: TranslitLexicon, val beamWidth: Int = 16) {
      fun decode(roman: String): List<Hypothesis>  // complete hypotheses, best first
  }

  class TranslitRanker(private val lang: TranslitLang, private val lexicon: TranslitLexicon) {
      fun rank(hypotheses: List<Hypothesis>, mapping: String?, boost: (String) -> Int): List<Candidate>
  }

  class TranslitEngine(
      val lang: TranslitLang,
      table: RuleTable,
      lexicon: TranslitLexicon,
      val mappings: CustomMappings,
      beamWidth: Int = 16,
  ) {
      fun suggest(roman: String, max: Int, boost: (String) -> Int = { 0 }): List<Candidate>
  }
  ```

Rules:
- The decoder expands each hypothesis with every rule from `matchesAt` at its offset. It prunes a hypothesis whose
  native output is not a lexicon prefix, unless the beam then becomes empty. Then it keeps the best `beamWidth` by
  cost. A word of more than 24 letters returns an empty list.
- The score is `-(ruleWeight * ruleCost) + lexiconBonus + frequency / 255.0 + mappingBonus + boost`.
  - `ruleWeight` is 1.0 for hi and 1.6 for ur, because every ur frequency is 16 (spec "Urdu frequency weakness").
  - `lexiconBonus` is 2.0. `mappingBonus` is 10.0. The values are tuned in Task 6.
- `suggest` returns at most `max` candidates. A user mapping is always first. Duplicates are merged and keep the best
  source.
- `SuggestDictionary.frequency` returns 0 for an unknown word. `SdictLexicon.frequency` maps 0 to null.
- `SdictLexicon` keeps only what it needs. If `LexiconMemoryTest` shows more than 6 MB for the ur lexicon, use the
  packed form from decision 6.
