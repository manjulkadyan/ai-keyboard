# Sprint 3: Suggestions and AI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Real on-device suggestions and opt-in autocorrect for every MVP subtype, with a per-locale user dictionary.
- A new backend `kb-api` with the full auth, quota, rate-limit and spend chain, an OpenAPI contract and an eval harness.
- The keyboard ✦ AI rewrite sheet and the post-dictation ✦ Polish flow, both streaming through that backend. Neither can ever overwrite host text that changed under it.

**Architecture:**

*Suggestions.* The engine is pure Kotlin in a new module `:core:suggest`:
- compact binary dictionary;
- Damerau-Levenshtein with keyboard-proximity costs, unigram plus bigram ranking;
- autocorrect decision.

`LatinLanguageProvider` (upstream) gets `FORK(S3-suggest)` hooks that delegate to it, one dictionary loaded per active subtype. Learned words live in a new Room table `user_word` in `:core:database`.

*Backend.* A separate Gradle project `../backend` (own git repo) on Ktor 3 and the official Anthropic Java SDK. Its storage (quota, rate limit, spend, reports, entitlement) is behind interfaces:
- in-memory fakes for tests;
- Firestore implementations whose tests run only when `FIRESTORE_EMULATOR_HOST` is set.

*Client.* Three layers:
- **Network:** `:core:network` (OkHttp plus auth-header interceptors fed by token-source interfaces) and `:core:firebase` (App Check and anonymous Auth, initialised lazily and only when Firebase options are configured).
- **AI client:** `:core:ai` (pure-JVM `AiClient`, SSE parsing, error mapping, client LRU).
- **IME:** `:ime:ai-ui` (controllers and Compose sheet). `:app` wires it through `AiImeSession`, which mirrors `TranslateImeSession`.

Host edits go through a new `SafeReplacer` in `:ime:editing`.

**Tech Stack:**
- *Shared:* Kotlin 2.2.20, coroutines/Flow, JUnit5 + Turbine.
- *Android:* Room 2.7.2 (KSP), Jetpack Compose, OkHttp 4.12.0 + `okhttp-sse` 4.12.0 (5.x needs compileSdk 37, see `libs.versions.toml` note), MockWebServer 4.12.0, Robolectric 4.17, Firebase BoM 35.1.0 (`firebase-appcheck-playintegrity`, `firebase-appcheck-debug`, `firebase-auth`).
- *Backend:* Ktor 3.6.0 (Netty, SSE, content negotiation with kotlinx.serialization), `com.anthropic:anthropic-java` 3.3.0, `com.google.firebase:firebase-admin` 9.11.0, `com.google.cloud:google-cloud-firestore` 3.49.0, `com.nimbusds:nimbus-jose-jwt` 10.10, `com.atlassian.oai:swagger-request-validator-core` 3.0.0.
- *Toolchain:* Gradle 9.2.0, Java 17.

**Privacy and data handling**
- No user content in any log, analytics event, exception message, crash key, WorkManager data or backend log, on device or server (PC-10, PC-6, TRD §5.4). User content means typed words, suggestions, AI input or output, transcripts and report text unless the user ticked it.
  - The backend logs per call: uid hash, endpoint, `prompt_id@version`, model, token counts, latency, status.
  - Anthropic SDK exceptions are mapped to an error code and their messages dropped.
- **Learning gate (PC-1):** nothing is learned (user dictionary, bigram history) when `decision.allowLearning == false` or `isPrivateSession`.
  - Suggestions are hidden when `decision.allowSuggestionStrip == false`.
  - Autocorrect never fires in URL, email, password, number, phone or datetime fields, or with `IME_FLAG_NO_PERSONALIZED_LEARNING`.
- **AI gate (PC-1):** AI and Polish need `decision.allowAi && decision.allowCloud`. Check twice: the chip is hidden **and** the controller re-checks the live decision and the `FieldGeneration` before sending, before every host write and on every streamed delta.
- **Consent:**
  - Nothing is sent to the backend until `FeatureSettings.consentAiAt > 0`, set only by tapping "Agree" on the `consent_ai` screen in the app (a trampoline activity, not the IME window).
  - Auto-polish additionally needs `consentAutoPolishAt > 0` and Pro.

**Host text (TRD §4.1.3)**
- Preview first. The host changes only on Replace or Insert.
- Replace only after re-reading the captured range and matching its SHA-256.
- Every multi-call edit goes inside `beginBatchEdit`/`endBatchEdit`.
- Never delete by stored length.
- Undo lasts 5 s and restores only if the range still holds our output.

**Keys and secrets**
- No vendor key in the APK, RC, either repo or test fixtures. The backend reads `ANTHROPIC_API_KEY` from env (Secret Manager in prod).
- The device never calls an Anthropic host.
- `gitleaks`-style secret patterns are checked by a backend test over the repo tree.

**AI request settings (TRD §4.4.2, §11.4)**
- Models are backend config: `claude-haiku-5-5` by default, `claude-sonnet-5-5` as the step up, and `claude-opus-5-5` only as the eval reference, never in a production route.
- Thinking is adaptive (`ThinkingConfigAdaptive`), display omitted. Relay text deltas only.
- `OutputConfig.Effort.LOW` is always set.
- `cache_control` goes on the last stable system block.
- `max_tokens` is 1,024 for rewrite and 2,048 for polish.
- Input caps: 2,000 chars on the client, 4,000 on the server.
- Never guess SDK names. Compile against the jar (`javap`) when unsure.

**Timeouts and limits**
- Client: 10 s to the first text delta and 10 s idle between deltas → `Timeout` with Retry. After 4 s with no text the sheet shows "Still working…".
- Free tier: 10 actions/day.
- Pro tier: 150/day and 3,000/month.
- Rate limit: per-uid bucket of 10/min and per-IP bucket of 60/min.
- Quotas reset at UTC midnight.

**Analytics and copy**
- Analytics names are snake_case, ≤ 40 chars and ≤ 25 params, registry-checked; PRD §12 names are canonical.
- All user-visible copy goes in `strings.xml`: English only, translatable, no concatenation.
- Never derive anything (code, strings, word lists, prompts, eval cases) from either teardown APK. Word lists come only from the sources in decision 2.

**Banned**
- `fallbackToDestructiveMigration`. Room schemas are exported to `core/database/schemas/`.
- `Process.killProcess` and `System.exit`.
- Firebase auto-init at process start: `FirebaseInitProvider` is removed from the merged manifest.

## Decisions taken in this plan (flag to product if wrong)

1. **Backend is Kotlin + Ktor in `../backend` (OD-06), not deployed this sprint.**
   - It builds, tests and runs locally.
   - Deploy files are written but not run: `Dockerfile`, `deploy/cloudrun.yaml` (`min-instances=1`, `asia-south1`) and `deploy/README.md` with gcloud steps for Secret Manager, Firestore, Cloud Armor (per-IP 60/min) and the Play Integrity quota request.
   - The TRD exit "works end to end on a release build with App Check enforced" becomes a device-checklist row once the user deploys.
2. **Word lists.**
   - Sources:
     - `hermitdave/FrequencyWords` 2018 `*_50k.txt` (content CC-BY-SA-4.0) for en, es, fr, pt, id and ar.
     - The 2016 list for hi (no 2018 list).
     - urduhack `urdu-words` (MIT, no frequencies) for ur. Frequencies are synthesised as a flat low count, so Urdu ranks by edit distance and learned use only.
   - Raw lists are committed under `third_party/wordlists/<lang>/` with their LICENSE files and built into `app/src/main/assets/dict/<lang>.sdict` by a Gradle JVM tool `:tools:dictbuild`.
   - CC-BY-SA share-alike applies to the shipped dictionary files; attribution goes in `assets/dict/LICENSES.md` and the About screen's licence list. **Legal to confirm (OD-11).**
3. **Bigrams are learned only.** None of the reachable open sources has bigram counts. The engine and the format support a bigram table, the shipped files carry none, and the user dictionary records bigrams from accepted words when learning is allowed. Next-word prediction (no typed prefix) stays v1 (PRD FR-05).
4. **Suggestion and autocorrect defaults (PRD FR-05).**
   - Suggestions are on for every MVP subtype (AC1 asks for candidates on every subtype).
   - Autocorrect is opt-in per language, stored as `FeatureSettings.autocorrectLocales: Set<String>`, default `{en, es, fr, pt, id}`; ur, hi and ar are off.
   - Autocorrect fires on space only when the top candidate's score is ≥ `autocorrect_min_score` (0.7, a `:core:config` default).
   - "Clear learned words" lives in a new Typing settings screen.
5. **Remote Config is defaults-only.** New pure module `:core:config`: interface `RemoteConfig` plus `DefaultsRemoteConfig` holding
   - `ai_enabled_global=true`
   - `autocorrect_min_score=0.7`
   - `ai_still_working_ms=4000`
   - `ai_timeout_ms=10000`

   Firebase RC arrives when a Firebase project exists (S4). The forced-packages RC comment in `FlorisImeService` stays as is.
6. **Firebase is optional at build time.**
   - `:core:firebase` initialises `FirebaseApp` manually from Gradle properties `aikb.firebase.{projectId,appId,apiKey,projectNumber}` (empty by default). With empty options the token sources report `NotConfigured` and the ✦ chip is hidden.
   - Debug builds can instead use **dev auth**:
     - Gradle property `aikb.ai.devAuth=true` plus `aikb.ai.baseUrl=http://10.0.2.2:8080`.
     - A debug-only network security config permits cleartext to `10.0.2.2` and `localhost` only.
     - The backend accepts `X-Dev-Uid` only when `AUTH_MODE=dev`, and refuses to start in dev mode when `K_SERVICE` is set (that is, on Cloud Run).
7. **No per-install identifier is sent.** TRD §5.4 asks for a per-install rate-limit bucket, but PRD FR-15 AC7 forbids device identifiers beyond the App Check token and the anonymous uid. The PRD wins: the backend rate-limits per uid and per client IP only.
8. **Integrity and Pro are interfaces only this sprint.**
   - `TierResolver` returns PRO only when an entitlement record says so **and** a cached integrity verdict is ≤ 24 h old (TRD §11.4). Both stores are empty until S4's `/v1/entitlement/verify`, so everyone is FREE.
   - The Pro quota path is still implemented and tested with fakes.
9. **Gemini Nano (OD-20) is not built.** `:core:ai` defines `AiEngine` with one implementation, `CloudAiEngine`, so Nano can slot in; `ai_request{engine}` is always `cloud`. `docs/decisions/od-20-gemini-nano.md` records the probe plan (AICore availability check, per-language quality vs the eval set, latency) and the decision "cloud only for MVP until the spike runs on device".
10. **Text captured for rewrite.**
    - The selection, if any.
    - Otherwise the whole field when it is ≤ 2,000 chars.
    - Otherwise the last ≤ 2,000 chars before the cursor, starting at a paragraph or word boundary.

    The captured range, not the cursor, is what Replace targets.
11. **Polish preview stays in the sheet.** The dictated span is not rewritten as composing text while streaming (TRD §8 "composing preview" read as "preview", safer under PC-1). The span is tracked as `[startOffset, endOffset)` plus its text, recorded by `VoiceImeSession` when a dictation session ends.

## Review Focus

1. **Host text changed between capture and Replace.** The user, the host app or an autofill changes the captured range while the response streams, or the user switches field, or the dictated span is edited before Polish Replace. Replace must not touch the host. The sheet offers Insert instead, and Undo after a successful Replace restores only if our output is still in place. Covered by a property test in Task 9 and controller tests in Tasks 11 and 13.
2. **Field becomes sensitive, or the keyboard closes, mid-stream.** `onStartInput(password, restarting = true)`, `onFinishInputView`, or the decision flipping to `allowAi=false`: the stream is cancelled, the preview and LRU entries for that field are cleared, a late delta is dropped by field generation, and nothing is written. Covered in Tasks 11 and 13.
3. **Quota counted once and refunded correctly.**
   - A retry with the same `client_req_id` counts once.
   - An upstream failure before the first text token refunds.
   - A failure after the first token does not.
   - Two concurrent requests at 9/10 leave exactly one allowed.
   - A day boundary during a request counts on the day it started.

   Covered in Task 6.
4. **No user text leaves via logs or errors.**
   - Every backend error path, including an SDK exception whose message echoes the prompt and a malformed JSON body: the captured log output and the error response contain none of the request text.
   - On the client, `AiError` and analytics params contain no content.

   Covered in Tasks 5, 7 and 10.
5. **Autocorrect where it must not.**
   - URL, email, password, number fields; `NO_PERSONALIZED_LEARNING`; locales not in `autocorrectLocales`.
   - Words with digits, ALL CAPS, `@` or `/`; a word the user just reverted.

   None of these is auto-replaced on space, and none of them is learned in incognito. Covered in Tasks 1 and 4.

**Interfaces (Produces):**
- `object DictionaryFormat { fun write(out: OutputStream, locale: String, unigrams: List<Pair<String, Int>>, bigrams: List<Triple<String, String, Int>>); fun read(input: InputStream): SuggestDictionary }`. The format: magic `AKSD`, version 1, locale, a sorted word table with frequency bytes (0–255, log-scaled), then an optional bigram table. Unknown version → `IllegalArgumentException` with no content in the message.
- `class SuggestDictionary(val locale: String, …) { val size: Int; fun frequency(word: String): Int; fun bigram(prev: String, word: String): Int; fun containsExact(word: String): Boolean; internal fun candidatesNear(prefix: String, maxDistance: Int): Sequence<String> }`
- `object DamerauLevenshtein { fun distance(a: String, b: String, max: Int = 2, cost: (Char, Char) -> Double = { _, _ -> 1.0 }): Double }`. Optimal string alignment; returns `Double.POSITIVE_INFINITY` once the distance exceeds `max`.
- `class KeyProximity(rows: List<String>) { fun substitutionCost(a: Char, b: Char): Double; companion object { val QWERTY: KeyProximity; fun forLocale(locale: String): KeyProximity } }`. Costs: adjacent keys 0.5, others 1.0, case-insensitive. `forLocale` covers QWERTY for en, es, fr, pt and id, plus the shipped ar, ur and hi layouts read from the subtype key maps in `app/src/main/assets/ime/keyboard/` as row strings checked in here; a locale with no rows falls back to a uniform cost of 1.0.
- `interface LearnedWords { fun boost(locale: String, word: String): Int; fun bigram(locale: String, prev: String, word: String): Int; fun isBlocked(locale: String, word: String): Boolean }`
- `data class Candidate(val word: String, val score: Double, val isExactOrLearned: Boolean, val isTypedWord: Boolean)`
- `class SuggestEngine(private val dict: SuggestDictionary, private val proximity: KeyProximity, private val learned: LearnedWords) { fun suggest(typed: String, previousWord: String?, max: Int = 3): List<Candidate> }`. Rules:
  - The score is in [0, 1]: frequency, bigram and learned boost, discounted by weighted edit distance.
  - Prefix completions rank above corrections only when the typed text is ≥ 2 chars.
  - Case follows the typed word (Capitalised and ALLCAPS).
  - The typed word appears first when it is a dictionary word or learned.
  - Blocked words never appear.
- `object AutocorrectPolicy { fun shouldAutocorrect(typed: String, top: Candidate?, minScore: Double, localeEnabled: Boolean, fieldAllows: Boolean, recentlyReverted: Boolean): Boolean }`. Returns `false` when:
  - `!localeEnabled || !fieldAllows || recentlyReverted`
  - `typed` contains a digit, `@`, `/`, `.` inside the word or `_`
  - `typed.length < 2`
  - `typed` is ALL CAPS and length > 1
  - `typed` is itself a dictionary or learned word
  - `top == null || top.isTypedWord || top.score < minScore`

- [ ] **Step 1: Write the failing tests**
  - `DamerauLevenshteinTest`:
    - `distance("teh","the") == 1.0` (transposition)
    - `distance("helo","hello") == 1.0`
    - `distance("abc","xyz", max = 2).isInfinite()`
    - a proximity cost makes `distance("hwllo","hello", cost=QWERTY::substitutionCost) == 0.5`
  - `DictionaryFormatTest`: write then read round-trips 1,000 words and 10 bigrams; frequencies keep their order; a bad magic or version throws, and the message does not contain the input bytes.
  - `SuggestEngineTest` (dictionary from `TestDictionaries.en()`: the, they, then, hello, help, world with frequencies):
    - `suggest("teh")[0].word == "the"`
    - `suggest("Teh")[0].word == "The"`
    - `suggest("hel").map{it.word}` contains `"hello"` and `"help"`
    - a learned boost lifts a rare word above a common one
    - a blocked word is absent
    - the max is honoured
  - `AutocorrectPolicyTest`: one test per `false` rule above, plus `shouldAutocorrect("teh", Candidate("the",0.9,…), 0.7, true, true, false) == true`.
  - `SuggestPerfTest`: on a synthetic 50,000-word dictionary, 1,000 random 1–8-char queries have p90 < 10 ms on the JVM. This is a guard; the device budget is 30 ms p90 (TRD §6.4).
