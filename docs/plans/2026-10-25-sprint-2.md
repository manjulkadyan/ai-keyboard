# Sprint 2: Translation core and surfaces — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On-device translation everywhere a user meets text: a pure translation core with a router, ML Kit engine and language ID, an offline-packs manager, the in-keyboard Translate bar that can never delete host text, a full Translator screen with history and TTS, and the system "Translate" selection/share sheet. Measure ML Kit latency on day 1 and write up ur/hi/ar/bn quality.

**Architecture:** Engine-agnostic logic (engine interface, router, LRU, sentence chunking, source detection rules, the debounce/`mapLatest` bar pipeline, translator pooling) lives in a new pure-Kotlin module `:core:translate` that builds and tests without Android. ML Kit sits behind it in `:core:translate-mlkit`; Room history in `:core:database`; TTS in `:core:tts`. The keyboard side is `:ime:translate-ui` (bar controller and Compose bar), which reuses the Sprint 1 composing-span code after it moves from `:ime:voice-ui` to a new pure module `:ime:editing`. `:app` wires everything through `FORK(S2-*)` hooks, the same way Sprint 1 wired voice (`TranslateImeSession` mirrors `VoiceImeSession`; app-scoped objects are lazy fields on `FlorisApplication`, no DI library). The cloud engine is an interface plus a disabled stub only (OD-05).

**Tech Stack:** Kotlin, coroutines/Flow (`debounce`, `mapLatest`), Jetpack Compose, ML Kit Translation `com.google.mlkit:translate:17.0.3` and Language ID `com.google.mlkit:language-id:17.0.6`, `kotlinx-coroutines-play-services` 1.10.2 (`Task.await()`), Room 2.7.2 (upstream's pin) with KSP, WorkManager 2.12.0, Android `TextToSpeech`, JUnit5 + Turbine, Robolectric 4.17 (JUnit4 vintage), `java-test-fixtures` for shared fakes.

**Spec:** `../product_docs/TRD.md` (§2.3, §3.1, §3.2, §4.1.1, §4.1.3, §4.3, §4.6, §6.1–6.4, §8 Sprint 2, §9 R-03, §10 OD-05, §11.5) and `../product_docs/PRD.md` (FR-07, FR-11, FR-12, FR-13, FR-14, FR-26, FR-32, FR-36, §11 PC-1/3/6/10, §12, OD-07, OD-17). TRD §8 uses its local FR ids (FR-04..07); the PRD ids are FR-11..14 (+ FR-26, FR-32, FR-36). TRD §11 overrides the TRD body; the PRD is authoritative for event names and acceptance criteria.

## Decisions taken in this plan (flag to product if wrong)

1. **Cloud translation is an interface and a disabled stub only** (OD-05 still open). `CloudTranslationEngine` reports `CLOUD_ONLY` for `ps` and returns `Failed(CLOUD_UNAVAILABLE)` for everything; the router can only select it when Pro **and** `cloudTranslateOptIn` **and** `decision.allowCloud`, and Pro is hard-wired `false` until S4. No backend, no INTERNET use by translation except ML Kit model downloads. The cloud first-use disclosure (TRD §6.2) ships with the real engine.
2. **One language pair for all surfaces.** The bar, the Translator screen and the selection sheet share `FeatureSettings.translatePair` (set in onboarding O4); each surface can swap or change it and the change is shared. TRD §3.2's separate `bar_source_lang`/`bar_target_lang` keys collapse into that one pair plus `barMode`.
3. **Romanised language-ID results are not trusted.** ML Kit Language ID returns tags such as `hi-Latn` for Hinglish; ML Kit translation would treat that text as Devanagari Hindi and produce garbage. Any `*-Latn` result for a non-Latin-script language, `und`, or confidence < 0.5 keeps the user's last source language (PRD FR-11 AC2). Proper Roman Urdu / Hinglish handling is S6 (FR-24).
4. **No `language_model_state` Room table this sprint.** ML Kit's `RemoteModelManager.getDownloadedModels()` is the source of truth (TRD §11.5 #5.2); we keep an in-memory `StateFlow` refreshed on app resume, when the bar opens and when a download job finishes. The Room mirror is added only if the bar's open-to-status time is too slow on device.
5. **Low-tier R-03 mitigation ships now, keyed on RAM.** Devices with `ActivityManager.isLowRamDevice` or total RAM < 4 GiB get a 600 ms bar debounce (others 450 ms) and live-composing defaults off. Remote Config `bar_debounce_ms` (400–500) waits for S3 Remote Config; the value is a constant until then.
6. **Translator history saves one row per edit session**, not one per debounced preview: the row of the current session is updated as the user types and a new row starts after clear, swap, pair change or leaving the screen (PRD FR-12 AC1 "every successful translation" read as "every finished translation"). History on by default, toggle in the screen's overflow (Settings screens are S4).
7. **Translator screen mic uses the Sprint 1 `SpeechSession` with the platform recognizer only** (Whisper stays a keyboard fallback this sprint); the camera entry is hidden until S5 (FR-20).
8. **No "speak" in the keyboard bar this sprint.** TTS ships in the Translator screen and the selection sheet; TRD §4.6 allows it in the IME but FR-13 does not require it, and it would put a `TextToSpeech` instance into the IME's memory budget.
9. **`translate_error.reason` gains `other`** (ML Kit internal errors, unsupported pair) next to PRD §12's `no_pack/timeout/net/quota`, and `translate_done` uses PRD §12's `src`/`tgt` params (FR-13 AC7 writes `pair`; §12 is canonical). `deeplink_unknown` (TRD §4.3.4, not in PRD §12) is added with no params.
10. **ur/hi/ar/bn quality write-up is a method plus machine output, not the native-speaker verdict.** The sandbox has no device and no raters: we ship the 200-sentence-per-language corpus, an instrumented harness that writes ML Kit output to CSV, and a rating template; the ratings and the "Beta" labels (FR-11 AC5) are filled in once native speakers score it. The exit criterion is marked partially met until then.
11. **ML Kit telemetry.** ML Kit pulls `com.google.android.datatransport` and may send anonymous SDK usage/diagnostic data to Google (no text). This sprint documents it in `docs/data-flows.md` for the Data safety form; turning it off is not exposed by the SDK. Product/legal to confirm the Data safety wording.
12. **Onboarding O4 offers the pair download** (Sprint 1 decision 8 deferred it here): a non-blocking "Download for offline (about N MB)" row on the languages step, Wi-Fi only by default. It never blocks completing onboarding.
13. **Composing helpers move to `:ime:editing`.** `TextTarget` and `ComposingSpanController` move unchanged (package rename only) from `:ime:voice-ui` so the bar and voice share one implementation and one set of safety tests.
14. **16 KB alignment is enforced for 64-bit ABIs only.** [Google's page-size guide](https://developer.android.com/guide/practices/page-sizes) says "all apps targeting Android 15 (API level 35) and higher must support 16 KB memory page sizes on 64-bit devices on Google Play" (deadline for app updates: 2027-02-01), and its `check_elf_alignment.sh` flags only arm64-v8a and x86_64. ML Kit's prebuilt 32-bit `libtranslate_jni.so` and `liblanguage_id_l2c_jni.so` (armeabi-v7a, x86) have 0x1000 alignment; every 64-bit ABI passes. We keep ML Kit as is: `scripts/check-16kb-alignment.sh` fails only on unaligned arm64-v8a/x86_64 libraries and lists 32-bit ones as informational. The debug APK grows 45.2 MB -> 111.7 MB because it carries all four ABIs; an App Bundle gets per-ABI splits (the `bundle {}` block in `app/build.gradle.kts` disables only the language split), so a Play download carries one ABI. Nothing builds an AAB yet: CI runs `assembleDebug` and Task 14 runs `assembleRelease`.
15. **Preview is the default bar mode; the Preview/Live switch lives in Settings (Sprint 4), not in the bar** (product, 2026-10-25). Until then `setMode` has no UI; low-tier devices stay in Preview.
16. **"Make this app private" stays exempt from the 3-pin limit** (PRD FR-07; product, 2026-10-25). It is a contextual safety control, not a pinned action. Long-pressing the lock makes the app private at once and shows an in-keyboard "App made private · Undo" message for about 5 s (in progress).
17. **One branch for the sprint** (product, 2026-10-25): work stays on `sprint-1-close-sprint-2-start` until Sprint 2 is done, then it merges to main in one go; the branch is backed up to origin.

## Known limitations (accepted by product, 2026-10-25)

Both need a timing race plus identical text: the host types text equal to our last commit before `onUpdateSelection` reports it, so a check of "the text before the cursor equals what we wrote" matches the host's text instead of ours. Closing them means reworking how voice adds trailing spaces; accepted instead.

1. **Voice trailing-space join.** The ", " / ". " join can delete the host's space instead of ours (`:ime:editing` property test, 30,000 seeds, seed 1326; not hit at the default 1,000).
2. **Bar undo with identical host text.** `undo()` via `deleteBeforeCursorIfEquals` can remove the host's identical text instead of our insert (Review Focus 5).

## Review Focus

1. **Bar never deletes host text.** Random key/backspace/host-edit/cursor-move sequences plus slow and out-of-order engine responses, in both preview and live-composing modes, must leave every character that existed before the bar opened unchanged (PRD FR-13 AC1). Property test in Task 6 (harness) and Task 7 (controller), Robolectric end-to-end in Task 8.
2. **Field becomes sensitive while the bar is open** (`onStartInput(password, restarting = true)` mid-request): the bar closes, buffer/preview/LRU entries for that field are cleared, a live-composing span is removed only if still verified ours, and a late engine result is discarded by sequence number and field generation. Test in Task 7 and Task 8.
3. **At most one in-flight request; stale results never shown.** `mapLatest` cancels the previous request; a result whose sequence number is older than the latest is dropped even if cancellation was ignored by the engine (ML Kit `Task`s cannot be cancelled). Test in Task 1.
4. **Failures never erase output or write empty text.** Offline without packs, model download failure, engine exception, cloud-only pair: last good preview stays, an inline status chip appears, nothing is committed. Test in Task 1 (pipeline) and Task 7 (controller).
5. **Undo restores only our own write.** Undo within 5 s removes the inserted translation only if the text right before the cursor still equals it, and puts the source text back in the bar buffer; otherwise it does nothing to the host. Test in Task 7.
6. **Process-start and memory budget.** The keyboard showing does not initialise ML Kit or load a model; a loaded `Translator` closes after 60 s idle or on trim. Test in Task 3 (manifest + pool) and checklist row in Task 14.
7. **Exported `TranslateTextActivity`** accepts only `PROCESS_TEXT`/`SEND` `text/plain`, survives fuzzed extras, never returns a result for read-only text and never shows an ad. Test in Task 11.
