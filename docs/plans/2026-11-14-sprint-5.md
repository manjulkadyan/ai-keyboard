# Sprint 5: v1 surfaces (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- An offline English dictionary with online enrichment through kb-api, a "Define" text action and a definition card in
  the keyboard.
- A phrasebook of our own phrases, with user phrases, favourites, speech and "Send via keyboard".
- A sticker panel in the keyboard with free and Pro packs, a signed catalog and the `commitContent` chain.
- The clipboard panel finished: text encrypted at rest, smart chips for email, URL and phone, and pinning.
- An HSV colour picker with hex input and 8 recent colours, used by a new "Custom colours" theme.
- Exit: every CI gate green, the device checklist done, and the content pipeline ready for the real content.

**Architecture:**

*Content.* A new JVM tool `:tools:packbuild` builds every data file that the app downloads or bundles.
- It builds the dictionary pack (SQLite), the phrasebook database (SQLite) and the sticker packs (PNG).
- It writes one content manifest and signs it with ECDSA P-256, like the S4 entitlement signature.
- The repo holds only small fixture sets that we wrote or generated. The real content is outside engineering (decision
  1).

*Device.* A new Android module `:core:content` holds the shared parts.
- `ContentManifest`, `ManifestVerifier`, `ContentSource` (HTTP, or app assets in debug) and the SHA-256 checked
  `PackDownloader`.
- The read-only readers `DictionaryPackReader` and `PhrasebookReader` open the SQLite files directly, without Room.
- The repositories `DictionaryRepository`, `PhrasebookRepository` and `StickerRepository`.
- User data goes in `:core:database` (`AppDatabase` version 3): the online dictionary cache, sticker packs, user phrases
  and favourites.

*Backend.* kb-api in `backend/` (git submodule) gets `POST /v1/dictionary`.
- It proxies one upstream source behind a `DictionarySource` interface and normalises the answer to our schema.
- The client `DictionaryClient` lives in `:core:ai`, next to `QuotaClient` and `AccountClient`.

*IME.* A new module `:ime:stickers-ui` holds the sticker panel composable and its controller.
- The panel opens as a new `ImeUiMode.STICKERS`. The STICKERS chip gets a key code.
- `fork/stickers/StickerInserter` in `:app` runs the insert chain: `commitContent`, then a share intent to the host,
  then the clipboard.
- The Pro gate reaches the IME as `() -> Boolean` through `proGate(featureSettingsStore)`.

*App.* The Dictionary and Phrasebook screens live in `:app` under `fork/dictionary` and `fork/phrasebook`.
- The HSV picker lives in `fork/themes/color`, with its colour math in `:core:theme`.
- The clipboard work stays in upstream `ime/clipboard` plus `fork/clipboard`, behind FORK hooks.

**Tech Stack:**
- *Android:* Kotlin 2.2.20, coroutines/Flow, Compose, Room 2.7.2, WorkManager, JUnit5 + Turbine, Robolectric 4.17,
  MockWebServer 4.12.0.
- *New tool library:* `org.xerial:sqlite-jdbc` 3.54.1.0, in `:tools:packbuild` only. It never goes in the APK.
- *Backend:* Ktor 3.6.0 and the existing kb-api stack. No new backend library.
- No new Android runtime library. `scripts/check-data-flows.sh` therefore needs no new artifact row.
- Versions were checked on Maven Central on 2026-11-14. Never guess an API name. If you are not sure, compile against
  the jar (`javap`).

- Every edited upstream file also gets a row in `docs/FORK_PATCHES.md`.

**Privacy and data handling**
- No user content in any log, analytics event, exception, crash key or backend log (PC-10, TRD §5.4).
  - User content means typed text, suggestions, transcripts, AI input or output, clipboard text and host package names.
  - In this sprint it also means dictionary queries, user phrases and the text of smart chips.
- No sticker request and no clipboard capture in a sensitive field (PC-1, PRD FR-23 AC3, FR-06 AC3).
- The keyboard never sends a typed word to the network. Online dictionary lookups start only from an explicit app action
  (decision 6).
- The catalog fetch and pack downloads carry no user identifiers: no auth header, no App Check token, no query string,
  no cookie (FR-23 AC4).
- The IME never shows an ad. The Dictionary screen gets one native ad below the fold. The keyboard surfaces (K-07, K-08)
  get none.
- Every feature that sends or stores data adds a row to `docs/data-flows.md` in the same task.
- New tables with user data are cleared by `fork/privacy/DataWiper`. `AppDatabase` is not in the backup rules, so it is
  not backed up.

**Keys and secrets**
- No vendor key in the APK, RC, either repo or test fixtures.
- The content signing private key lives outside both repos. The APK holds only the public key, from the Gradle property
  `aikb.content.publicKey`.
- If `aikb.content.publicKey` is empty, a release build fails. Debug and beta fall back to the fixture test key
  (decision 12).

**Analytics and copy**
- Event names are snake_case, at most 40 chars and 25 params, registry-checked. PRD §12 names are canonical.
- New events: `dictionary_lookup{offline,found}` and `sticker_send{pack_id,premium,method}`. Pack downloads reuse
  `pack_download_start/done`.
- All user-visible copy goes in `values/strings_fork.xml` (or the module's own `strings.xml`). English only,
  translatable, no concatenation.

**Banned**
- `fallbackToDestructiveMigration`, `Process.killProcess`, `System.exit`.
- Deriving any code, art, phrase, definition or copy from either teardown APK. The App H phrasebook DB is on the
  do-not-copy list.
- Committing a CC-BY-SA dictionary extract to the repo (R-08). The real pack ships only as downloadable data.

## Decisions taken in this plan (flag to product if wrong)

1. **Content work is outside engineering.** The Wiktionary extract, the about 300 phrases, their translations and the
   sticker art come from content owners. Engineering ships the pipeline, the formats and small fixture sets:
   - A dictionary fixture of about 50 English entries that the team wrote (Apache-2.0).
   - A phrasebook fixture of 12 categories with 3 English phrases each (36 phrases), written by the team.
   - Two sticker packs of 8 images each, generated by `:tools:packbuild` from shapes and colours: `starter` (free) and
     `starter_plus` (Pro).
   - `assets/LICENSES.md` records each set. Each pack also carries its licence in the manifest (FR-23 AC2).
2. **The S5 plan is 9.25 days, not the 7.5 days of TRD §8 and §8.1.** The extra 1.75 days are:
   - Clipboard encryption at rest, moved here by S1 decision 2 (0.5 day).
   - A "Custom colours" theme slot, because no custom theme editor exists for the picker (0.5 day).
   - The shared content pipeline and the manifest signature (0.75 day).
3. **No `:feature:*` modules.** TRD §2 names `:feature:dictionary`, `:feature:phrasebook` and `:feature:stickers`. The
   module rules forbid `:ime*` to reach `:feature:*`, and the sticker panel is IME code. So the shared code goes in
   `:core:content`, the panel in `:ime:stickers-ui`, and the screens in `:app` under `fork/*`.
4. **One signed content manifest.** `<content base>/v1/manifest.json` plus `manifest.json.sig` lists the dictionary and
   sticker packs. TRD §4.9 names `stickers/manifest.json` for stickers only. One file means one signature check and one
   24 h cache.
5. **Read-only content is plain SQLite, not Room.** The dictionary pack (about 40 MB) and the phrasebook DB open with
   `SQLiteDatabase.OPEN_READONLY`. Room `createFromAsset` copies the file and needs a destructive path on each content
   update. Room keeps only user data.
6. **Online dictionary lookups need an explicit app action.** The app Dictionary screen and the "Define" text action can
   call kb-api. The keyboard card is offline only. Its "More" button opens the app screen. A setting "Online dictionary"
   (default on) turns the network off.
7. **The dictionary covers English only in S5.** ur, hi and ar packs are v1.x (PRD FR-21). `dictionary_entry.lang` keeps
   the column for them.
8. **`dictionary_translation` waits.** The S5 backend returns no translated glosses, so the table has no data to hold.
   It comes with the first source that has translations.
9. **The bundled `starter` sticker pack works with no network.** It is in `assets/stickers/starter/`. Other packs
   download on a tap. The `starter_plus` premium fixture pack is in debug assets only, so testers can try the gate.
10. **No sticker search in S5.** Keywords are stored for later. Search needs typed text in the panel, and PC-1 rules for
    sensitive fields then apply.
11. **`sticker_send.method` adds a `clipboard` value** for the third fallback. The PRD lists only `commit_content` and
    `share`.
12. **Fixture signing key.** A test-only P-256 key pair signs the fixture manifest. The private key is in
    `tools/packbuild/src/test/resources/fixture-signing-key.pem`. It is not a vendor key and it signs only fixtures. The
    release public key comes from `aikb.content.publicKey`.
13. **Shared files are deleted by a sweep, not after `commitContent`.** The host reads the URI after `commitContent`
    returns. So a sweep deletes files in `cache/share/` that are older than 24 h. It runs at IME start and at each panel
    open.
14. **The FileProvider keeps the upstream `backup` root.** TRD §6.3 asks for a single `share` root. The upstream backup
    screen needs `backup-and-restore/`. We add `share/` and nothing else.
15. **Clipboard encryption covers the text column.** Image and video clips stay as files in app-private, no-backup
    storage, as upstream keeps them. A lost Keystore key deletes all clipboard rows (TRD §11.6).
16. **The eyedropper is built but hidden.** It needs a custom background image, and photo backgrounds are v1 with no
    sprint yet (S4 decision 7). `ColorSampler` and its tests ship. The button appears only for a theme with an image
    background.
17. **"Custom colours" is one free theme slot.** The user picks colours for keys, key text, keyboard background and
    accent. The rest is derived. PRD §10.2 lists "basic custom" as free.
18. **"Send via keyboard" opens the share sheet.** The app has no input connection to another app. The share sheet sends
    the phrase into the chat app. This is our own phrase text or the user's own phrase.
19. **The phrasebook has no native ad in S5.** Screen S-17 lists "Native", but no `native_phrasebook` placement exists
    in PRD FR-27 or the TRD placement table.
20. **New allow-listed routes `dictionary` and `phrasebook`.** PRD FR-32 does not list them. The keyboard card's "More"
    button needs `dictionary`. The routes carry no query values. The word goes in an intent extra.
21. **A long-press on a suggestion always opens the definition card.** For a learned word, the card also has "Remove
    suggestion", which keeps the upstream action.
22. **Pack downloads report `kind=dict` for the dictionary and a new `kind=stickers`.** `PackKind.DICT` exists already.
23. **Phrase translations are machine translated at runtime in S5.** ML Kit fills each target from the on-device pack.
    The row shows "Machine translated" (TRD §4.10). The reviewed top-10 translations replace them later.

## Review Focus

1. **A sticker in the wrong place.** No sticker request happens in a sensitive field, on a locked device or in
   incognito. A lapsed Pro gets no premium insert.
   - If `allowCloud` is false, the chip hides. The panel closes on a policy change. The inserter checks Pro again at
     insert time.

   Covered in Task 6.
2. **User content leaving the device.** A typed word never reaches the network from the keyboard. A dictionary query
   never appears in device logs, backend logs or analytics. Catalog and pack requests carry no identifier. Covered by
   MockWebServer and log-capture tests in Tasks 2, 3 and 4.
3. **FileProvider exposure.** Only files in `cache/share/` get a URI. The grant is read-only and goes to the receiving
   app only. A path outside the root throws. Covered in Task 6.
4. **Clipboard key loss and the first encrypted start.** Plaintext rows from S1 to S4 are encrypted once. A wrong key or
   a bad tag deletes the rows and never shows ciphertext. No plaintext text stays in the database file. Covered in Task
   7.
5. **A tampered manifest or pack.** A bad signature, an unknown key, a missing field or a SHA-256 mismatch is rejected.
   The last good manifest and the installed packs stay in use. Covered in Task 2.

    ```sql

    -- keys: format=1, lang, version, source, licence_name, licence_url, attribution
    ```

  - The manifest JSON:

    ```json
    {"format":1,"issued_at":0,"packs":[{"id":"starter","kind":"stickers","version":1,"premium":false,
    ```

- `headword_norm` is NFC, lower case (`Locale.ROOT`) and trimmed. The device uses the same function (Task 2 copies it,
  and a test pins both).
- The builder keeps the first 3 senses per headword and part of speech. It drops entries without a gloss.
- Before Step 3, check the kaikki field names (`word`, `pos`, `senses[].glosses`, `senses[].examples[].text`,
  `synonyms[].word`) against one real line. Do not guess them.
- Sticker art is 512 x 512 PNG, at most 60 KB each, drawn with `java.awt` in headless mode from the seed. The output is
  deterministic.
- Builds are deterministic: the same input gives the same bytes (fixed `issued_at` from the arguments, sorted rows,
  `VACUUM` at the end).

**Interfaces:**
- Consumes: the manifest format and the fixture key (Task 1), `HttpClientFactory.create(tokens = null)`.
- Produces:
  ```kotlin
  data class ContentManifest(val format: Int, val issuedAt: Long, val packs: List<PackSpec>)
  data class PackSpec(val id: String, val kind: PackKindSpec, val version: Int, val premium: Boolean,
                      val title: String, val files: List<PackFile>, val licence: PackLicence)
  enum class PackKindSpec { DICT, STICKERS }

  class ManifestVerifier(publicKeyBase64: String) {
      fun verify(manifest: ByteArray, signatureBase64: String): ContentManifest? // null on any failure
  }
  interface ContentSource { suspend fun fetch(path: String): ByteArray } // throws ContentFetchException
  class ManifestCache(dir: File, source: ContentSource, verifier: ManifestVerifier, clock: () -> Long) {
      suspend fun current(): ContentManifest? // network at most once per 24 h; last good copy otherwise
  }
  class PackDownloader(source: ContentSource, root: File) {
      suspend fun install(pack: PackSpec): Outcome<File> // files/content/<kind>/<id>/<version>/
      fun remove(packId: String)
  }
  object HeadwordNorm { fun of(word: String): String }
  ```
- New `AppDatabase` tables (version 3):
  - `dictionary_entry(id INTEGER PK, lang, headword, headword_norm, pos, definition, example NULL, source, fetched_at)`
    with `idx(lang, headword_norm)`. Only `source = 'online'` rows live here (decision 5).
  - `sticker_pack(id TEXT PK, title, version INT, is_premium INT, manifest_url, downloaded INT, updated_at)`.
  - `sticker(id TEXT PK, pack_id FK CASCADE, file_path, mime, keywords)` with `idx(pack_id)`.
  - `user_phrase(id INTEGER PK, text, translation NULL, target_lang NULL, created_at, updated_at)`.
  - `phrase_favourite(phrase_ref TEXT PK, created_at)`. `phrase_ref` is `c:<id>` for our phrases and `u:<id>` for user
    phrases.

Rules:
- `HttpContentSource` uses a client without `AuthHeadersInterceptor`, without a cookie jar and with the fixed User-Agent
  `AIKeyboard-Content/1`. The path has no query string.
- `AssetContentSource` reads `assets/content/v1/`. It is used only in debug builds with an empty `CONTENT_BASE_URL`.
- With an empty base URL in beta or release, `ManifestCache.current()` returns null and the screens show "Not available
  in this build".
- The downloader writes to a `.part` file, checks the size and SHA-256, then renames. A mismatch deletes the file and
  returns an error.
- It logs pack ids and sizes only. `pack_download_start/done` carry `kind`, never a URL.
- Downloads run in WorkManager with `NetworkType.UNMETERED` while the "Wi-Fi only" setting is on (new
  `FeatureSettings.contentWifiOnly = true`).

- [ ] **Step 1: Write the failing tests**
  - `ManifestVerifierTest`: a good signature parses. A changed byte, an empty signature, another key, `format = 2` and a
    missing `sha256` each give null.
