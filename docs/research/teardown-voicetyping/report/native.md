# Team 4: Native, ML & Media/UX

**App:** Voice Keyboard - Voice Typing · `com.logiapps.language.keyboard.voice.typing.translator` · v1.3 (versionCode 4) · sha256 `6052cf1a…c6f8`
**Stack:** Kotlin + Jetpack Compose, Hilt, Room, DataStore, coil3, Lottie. R8-renamed (`defpackage/*`, 10 684 classes). It is a fork of FlorisBoard (Apache-2.0).
**Pass:** static only. No device and no traffic. Tags: `[obs]` means read directly from dex, res, assets or binary. `[dec]` is a design decision for the clone. `[inf]` is inferred from a tell. Every runtime claim is `[inf]` and is listed in §12.
**Citations:** paths are relative to `voicetyping_work/`. `jadx_out/sources/` is shortened to `src/`, and `src/defpackage/` to `dp/`.

> **Headline.** The app has no first-party native code and no ML model files. Every "smart" feature uses either the platform (SpeechRecognizer, TextToSpeech), Google Play services (legacy GMS Vision OCR loaded through dynamite), or the network (an unofficial Google Translate endpoint and freedictionaryapi.com). The keyboard is upstream FlorisBoard's Compose IME, with these fork additions: a flat, preference-driven theme layer, a voice button, a translator bar, stickers, key sounds, an in-IME native ad, and per-language plain-text suggestion word lists. `[obs]`

## 4. Audio capture and speech pipeline

### 4.1 In-IME voice typing (`FlorisImeService.r()`, lines 735-760) `[obs]`

1. If a recognition is already running (`this.i`), return. If `SpeechRecognizer.isRecognitionAvailable(this)` is false, show the toast "Speech not available" and stop.
2. Destroy any previous recognizer, then call `SpeechRecognizer.createSpeechRecognizer(this)`. This uses the default service; no `ComponentName` is pinned.
3. Build the intent: `ACTION_RECOGNIZE_SPEECH`. Extras: `LANGUAGE_MODEL=free_form`, `LANGUAGE=<active subtype locale>.toLanguageTag()`, `PARTIAL_RESULTS=true`.
4. Attach listener `dp/yy2.java`, then call `startListening`.
5. `yy2.onReadyForSpeech` sets the "listening" StateFlow (`fu7`) to true and arms a **5 000 ms watchdog** (`p0` case 21, which calls `s()`).
6. `yy2.onResults` takes only `results_recognition[0]`:
   - If pref `showTranslatorBar` is on (`dp/g03.java` field `m`), the text goes into `hh8.a` (translator-bar state) and coroutine `as0` runs `my3.B0(text, hh8.c, hh8.d)`. The defaults are `c="en"` and `d="ur"`, and the persisted prefs `translatorSourceLangCode="en"` / `translatorTargetLangCode="ur"` override them. The translated text is then committed through `gh8`.
   - Otherwise it calls `InputConnection.commitText(text + " ", 1)`.
   - After either path it re-arms the 5 s watchdog.
7. `onError` calls `s()`, which runs stopListening, cancel and destroy, then `finishComposingText()`. `onPartialResults`, `onRmsChanged` and `onBufferReceived` are **empty**. Partial results are requested but never shown, and the mic animation is not driven by RMS. `[obs]` `voice.json` probably animates on the boolean flag instead. `[inf]`

**Permission path** `[obs]`: an IME cannot show a runtime-permission dialog, so `AudioPermissionActivity` requests `RECORD_AUDIO` (lines 58-98). After a grant it posts a delayed callback to `florisImeService.r()` (line 39) and calls `finish()`.

**Effect** `[inf]`: each mic tap is a single utterance. Recognition ends after the first final result plus 5 s of silence. There is no continuous dictation and no punctuation commands.

### 4.2 App-side voice (translator / conversation)

`dp/dn3.java:183-189` launches the system recognition activity through an ActivityResult launcher. Extras: `LANGUAGE`, `PROMPT "Speak now..."`, `MAX_RESULTS 5`, `PARTIAL_RESULTS true`. On failure it shows the toast "Voice search failed. Please try again." `[obs]`

### 4.3 Voice Conversation `[obs]` / `[inf]`

- The screen composable is `dp/ki1.java`. Its strings are `welcome_to_voice_conversation`, `tap_on_mic_start_speaking`, the "mic_pulse" animation label and "Swap Icon". `[obs]`
- Persistence is the Room table `conversation_messages(id, text, isLeft, translatedText, timestamp)`, with `SELECT … ORDER BY timestamp ASC` and a "Clear Conversation" action. `[obs]`
- Pref keys `CONVERSATION_SOURCE` / `CONVERSATION_TARGET` hold the two languages. `[obs]`
- Inferred flow `[inf]`: the left or right mic launches `dn3` STT in that side's language. The result is passed to `my3.B0` and stored with `isLeft`. TTS then speaks it (`dp/gi1.java:56-59` sets `Locale.forLanguageTag(code)` and calls `speak`).
- There is no "Conversation" nav route; this screen is probably a tab inside `TranslationScreenRoute`. `[inf]` (open item 3)

- `dp/vr6.java` constructs `new TextToSpeech(context, new as6())` at line 76. It is a splash or remote-config-fetch composable (log tag "remoteConfigLogs"), so it **pre-warms** TTS and does not play speech. `[obs]`

## 6. Suggestion and prediction engine

- **Registry** `[obs]`: `dp/go5.java:45` maps `org.florisboard.nlp.providers.latin` to `dp/am4` and `org.florisboard.nlp.providers.han.shape` to `ih3`. Every subtype (`dp/az7.java:35-42`) uses the Latin provider for both spelling and suggestions (`dp/jz7.java`).
- **Preload** `[obs]`: `am4.f()` launches `ad3` case 5 on `Dispatchers.IO`. Its `invokeSuspend` failed to decompile, but the strings `ime/dict/<lang>_suggestion.txt` are present in the `classes.dex` string pool. The words are loaded into a `LinkedHashMap<String, Int>` behind a mutex (`ig3`).
- **Suggest** (`am4.h`, lines 142-215) `[obs]`:
  1. Take the composing word. If there is none, scan back from the cursor to the last non-letter character that is not `'`.
  2. Lowercase it with `Locale.ROOT`.
  3. Return the first *N* map keys that `startsWith` the word, in insertion order.
  4. Each candidate gets a fixed confidence of 0.5.
  5. There is no edit distance, no bigram context, and no autocorrect scoring.
- **Frequency** `[obs]`: `am4.e()` returns `map[word] / 255.0`. The text files have no frequency column, so the stored values are constant or rank-derived. `[inf]`
- **Data quality** `[obs]` (computed with a Python profile of the files):

| File | Lines | ASCII-only | Arabic-script | Dups | Order |
|---|---|---|---|---|---|
| english_data | 20 002 | 20 002 | 0 | 2 | frequency (a, an, the, of…) |
| arabic | 23 712 | **19 244** | 4 466 | **9 080** | unsorted |
| urdu | 19 000 | 0 | 19 000 | 280 | unsorted |
| french | 15 000 | 8 853 | 0 | 0 | alphabetical-ish |
| spanish | 15 000 | 11 944 | 0 | 0 | alphabetical-ish |
| portuguese | 17 000 | 12 659 | 0 | 0 | unsorted |
| indonesian | 17 000 | 17 000 | 0 | 0 | sorted |

  About 81 % of the Arabic list is English words. The Hindi subtype (`hi-IN`, `az7.q`) has **no** dict file. Because suggestions follow file order, French and Spanish suggestions come out alphabetical rather than by frequency. `[inf]`
- **Upstream prefs kept** `[obs]`: `suggestion__enabled`, `suggestion__display_mode`, `suggestion__block_possibly_offensive`, `suggestion__incognito_mode`, `suggestion__api30_inline_suggestions_enabled=false` (`dp/n03.java`). Emoji suggestions use a leading-colon trigger, minimum query length 3, maximum 5 candidates (`dp/xz2.java:33-38`). Clipboard suggestion has a 60 s timeout (`dp/sz2.java:30-31`). User dictionary: `FlorisUserDictionaryDatabase` plus the system user dictionary.
- **Clone substitute** `[dec]`: use a frequency-weighted trie or FST built from an openly licensed frequency list (wordfreq is CC-BY-SA-4.0, Leipzig corpora have their own terms), and add Damerau-Levenshtein autocorrect plus a small bigram model. Do not reuse these word lists, because their provenance is unknown.

## 7. Keyboard view rendering and themes

### 7.1 Rendering architecture `[obs]`

- `FlorisImeService.onCreateInputView()` (line 433) returns `sy2`, which extends `q0`. `q0` is an `AbstractComposeView` (`extends ViewGroup`). The whole keyboard (keys, smartbar, panels) is **Jetpack Compose**, as in upstream FlorisBoard. There is no `KeyboardView` and no custom `onDraw` canvas.
- `onEvaluateFullscreenMode` follows the `keyboard__landscape_input_ui_mode` pref. `onEvaluateInputViewShown` also honours the physical-keyboard pref.
- Smartbar quick actions are the upstream set, including `voice_input` (strings `quick_action__*`).
- Key sounds come from a `SoundPool` (`dp/se4.java`) selected by `keyClickSoundEnable` / `keySoundEnable`. Vibration uses `keyPressVibration`.

### 7.2 Theme system: a fork layer over Snygg `[obs]`

## 10. Screen-by-screen UX flow, including keyboard-enable onboarding

1. **Splash:** Lottie animation, remote config, consent, then a splash interstitial or app-open ad. `[obs]` for the strings, `[inf]` for the order.
2. **First-run language** (`LanguageMainScreenRoute`), followed by a native ad. `[inf]`
3. **Enable keyboard, step 1 of 2** (`step_1_of_2`, `enable_keyboard.lottie`, button "Enable Keyboard"): opens `Settings.ACTION_INPUT_METHOD_SETTINGS` (`dp/ct0.java:63`). A coroutine **polls every 500 ms** (`dp/zt3.java:78-100`):
   - On API 34 and above it checks whether `getEnabledInputMethodList()` contains our package.
   - Below API 34 it parses `Settings.Secure.enabled_input_methods`.
   - This is the same pattern as the upstream FlorisBoard setup screen. `[obs]`
4. **Step 2 of 2** (`select_keyboard.lottie`, "Select Keyboard"): calls `InputMethodManager.showInputMethodPicker()` (`dp/ct0.java:57`, `dp/uh.java:244/268`). Selection is confirmed by checking `Settings.Secure.default_input_method`, which is unflattened and compared against `…/dev.patrickgold.florisboard.FlorisImeService` (`dp/hr0.java:31-38`). `[obs]`
5. **Home** (bottom nav) shows the feature cards. Each card shows an interstitial with its own placement, for example `home_translation_click` and `home_sticker_click` (Monetization team). `[obs]`
6. **In the keyboard:**
   - **Smartbar:** voice, translator bar, emoji, clipboard and stickers.
   - **Mic:** if `RECORD_AUDIO` is missing, the permission trampoline runs first. Then the system recognizer listens and commits the text, or translates and commits it.
   - **Translator bar:** a Translate-as-you-type or voice bar with an en to ur default.
   - **Stickers** are sent through `commitContent`. MIME types are tried in this order: `image/webp.wasticker`, jpeg, png, webp, gif. If the target app accepts none of them, it falls back to `xy` case 15. `[obs]` That fallback probably shares the file or shows a toast. `[inf]`
   - **In-IME native ad** (`dp/wy2.java:89-95`) shows only when all of these hold: `my_keyboard_native_ad_enable`, `!is_user_premium`, `PREF_CAN_USER_REQUEST_ADS`, and the host app is **not** on a hard-coded deny list of about 90 packages in `FlorisImeService.onStartInputView`. The list covers this app, Google apps (Search, Gmail, Chrome, YouTube, Play Store, Maps, Gboard, Messages, Docs, Photos, Translate…) and OEM or third-party launchers. `[obs]` It suppresses ads exactly where Google staff or reviewers are most likely to look. That is a policy-evasion tell and a high Play-policy risk. `[inf]`
7. `is_user_premium` is read, but no billing code exists. It is a vestigial flag from the white-label template. `[inf]`
